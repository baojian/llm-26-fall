## Experiment snapshot and reproduction

The September 16 rerun uses the same local inputs as the September 15 experiment.
`lecture02-results.json` records each input's byte length and SHA-256, the exact
ordered-document fingerprint of every data split, and normalized cross-split
duplicate counts. Original upstream commit revisions were not recorded at download
time. Match the recorded hashes before claiming an exact reproduction; newer
upstream files may yield different numbers.

| Local input | Recorded origin or role |
| --- | --- |
| `tinystories-train-head.txt` | First 62,914,560 bytes of `TinyStoriesV2-GPT4-train.txt` from [roneneldan/TinyStories](https://huggingface.co/datasets/roneneldan/TinyStories); discard the incomplete final story. |
| `tinystories-valid.txt` | `TinyStoriesV2-GPT4-valid.txt` from the same dataset. |
| `zh-000000.parquet` through `zh-000011.parquet` | `4_5/000000.parquet` through `4_5/000011.parquet` from [opencsg/Fineweb-Edu-Chinese-V2.1](https://huggingface.co/datasets/opencsg/Fineweb-Edu-Chinese-V2.1). |
| `wikitext103-train0.parquet` | `wikitext-103-raw-v1/train-00000-of-00002.parquet` from [Salesforce/wikitext](https://huggingface.co/datasets/Salesforce/wikitext). |
| `owt_shard0.parquet` | Original experiment's OpenWebText parquet slice; its exact upstream download URL was not retained. Identify this snapshot by its recorded hash. |
| `qwen3-tokenizer.json` | Original experiment's [Qwen/Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B) tokenizer; identify the version by its recorded hash. |

Split rules, using Python's zero-based slices:

- TinyStories: training from the complete training-prefix stories, capped at
  24 MiB; validation stories `[:400]` for dev and `[400:2400]` for test.
- OpenWebText: `[:-1500]` for training with a 24 MiB cap, `[-1500:-1200]`
  for dev, and `[-1200:]` for test.
- Chinese: shards 0–9 for capped training, first 300 documents of shard 10 for
  dev, and first 1,200 documents of shard 11 for test.
- Reference filter: reconstruct whole WikiText articles using top-level headings,
  cap at 24 MiB, then reserve the last 5% of selected articles for development.
  Internal paragraph breaks remain inside their article. The JSON distinguishes
  loaded, selected, training, and dev article counts.

A MiB is 1,048,576 bytes. The corpus cap includes the final complete document,
so its byte size can slightly exceed the cap. These lecture samples and the
Qwen3 tokenizer are separate from the data and learned BPE required by A1.
Document hashes preserve evaluated content; duplicate checks normalize NFKC,
case, and whitespace. They do not establish the absence of near-duplicates.

Place matching inputs in a local directory and use the course environment:

```sh
uv sync --extra tokenization --group dev
uv run python scripts/lecture02_experiments.py --data LOCAL_DATA --owt LOCAL_OWT.parquet --tokenizer LOCAL_TOKENIZER.json --out slides/.checks/lecture02-rerun
```

Inspect the results before updating published assets. `test_tokens` includes
one EOS prediction per document; `test_content_tokens` excludes EOS. Byte
counts cover the evaluated document text, excluding inter-document separators.
The filter Plotly chart uses shared bins and each population's percentage;
its cutoff is an illustrative course choice. The loop retains its original dev
and test splits while replacing training with 2,000 capped samples per round.
Its changing token budget is recorded and shown on hover. Neither experiment
establishes that a Wikipedia-like score is a universal quality filter.
