Choose a question you can test

Each card is a proposed investigation, not a promise that a paper's results will reproduce at this scale. The minimum outcome is designed for one student over the remaining semester, with roughly 4-6 hours of work per week. A well-supported negative result is a complete outcome. All students have the same requirements and maximum score under the published course policy.

Start small: one main dataset or generator, one model family, one baseline, and one controlled change. Freeze a development/evaluation split and record model revisions, prompts, seeds, budgets, and unsuccessful runs. Inspect at least 20 examples when the dataset permits. Use repeated runs or uncertainty estimates appropriate to the experiment. Reusing assignment code is welcome; identify the project's additional question and evidence.

Preparation: the first four lectures provide text processing, n-grams, evaluation, embeddings, PyTorch, and neural/recurrent models. Each card names what remains to learn. Attention, Transformers, tuning, retrieval, diffusion, and agents can be learned from the linked starter resources before their later lectures.

Compute estimates are planning targets, not allocations or measured runtimes. CPU, inference, training, and external-review labels describe resources, not grading tracks. Pilot 10 examples or 100 training steps, then reduce scope if needed. Paid APIs are optional; propose a spending cap before using them. Small-model projects should usually begin at 0.6B-2B for inference, 0.6B for adapter tuning, or 5M-30M when training from scratch.

How this updates the earlier project list

The Spring 2026 list combined older challenge tasks with recent papers. Standalone reproductions of SemEval-2014 sentiment classification, the Fake News Challenge, 2019/2020 commonsense tasks, and generic Kaggle classification are retired from this shortlist. Their datasets and simple methods can still serve as useful baselines.

BLT, sparse attention, difference-aware fairness, cross-lingual intervention, formal-language pretraining, and Infini-gram mini remain useful after reducing their scope. The reasoning-faithfulness project adds a 2026 control study. New directions include editable context, agent memory and security, Qwen-Scope, small diffusion checkpoints, current multimodal models, and upstream benchmark contributions. Foundational methods may be older; every project asks a current, bounded question.

01 Whose text costs more tokens?

Audit modern tokenizers on English, Chinese, code, and mixed text.

Case studyResearch problem

Question: Which tokenization gaps persist when document type and meaning are controlled?

Scope, evaluation, resources and sources
Minimum scope and data
Freeze 1,000 short documents from two languages and code; compare three released tokenizers including Qwen3.5. Add a 100-pair, manually checked English/Chinese parallel subset.
Baseline and controls
Byte and character counts, plus the course BPE tokenizer. Keep normalization and documents fixed.
Evaluation
Tokens per UTF-8 byte, tokens per character, paired token counts, round-trip failures, and robustness to spaces or Unicode variants. Token counts alone do not measure model quality.
Minimum complete outcome
A reproducible tokenizer audit with paired plots and 20 explained outliers.
Preparation
L01 tokenization; Python text processing and sampling.
Planning budget
Laptop, roughly 8-16 GB RAM; plan for at most 4 hours of processing and a small data download. An optional inference sanity check can use a shared GPU.
Risks and smaller fallback
Use 200 documents and two tokenizers; no model inference or training is needed.

Starting sources

  • Qwen3.5 small model release — Qwen Team; 2026. Model card
  • FineWeb2: One Pipeline to Scale Them All — Penedo et al.; 2025. Paper

02 Does number formatting change the answer?

Separate numeric token boundaries from changes to the mathematical problem.

Research problem

Question: Do digit grouping, leading zeros, or equivalent decimal notation systematically change small-model accuracy?

Scope, evaluation, resources and sources
Minimum scope and data
Generate 200 exact arithmetic problems with three meaning-preserving renderings. Use a 0.6B-1.7B model, at most 512 output tokens per problem.
Baseline and controls
Canonical numeral formatting and a Python exact-arithmetic oracle; pair every variant with its original.
Evaluation
Exact answer accuracy, consistency within pairs, token count, and errors by digit length. Do not attribute every formatting effect to tokenization alone.
Minimum complete outcome
A paired error analysis and one tested formatting intervention.
Preparation
L01 tokenization; L02 evaluation; learn model inference and robust answer parsing.
Planning budget
One 12-24 GB GPU or a suitable local quantized runtime; target at most 8 GPU-hours total on the scoped subset. Start with 0.6B-2B models, batch size 1, short contexts and capped outputs.
Risks and smaller fallback
Restrict to integer addition and multiplication, 100 examples, one model.

Starting sources

  • Language Models Encode Numbers Using Digit Representations in Base 10 — Levy et al.; NAACL 2025. Paper
  • Qwen3-0.6B — Qwen Team; 2025. Model card
