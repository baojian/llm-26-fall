Compare original pretraining checkpoints

The Wikipedia model list is our starting map of model families. The selection here is narrower: reviewed, general-purpose base checkpoints from the original developers or their maintained archives. Small models and text-capable multimodal bases qualify. The linked publisher cards establish each inclusion.

We select one size for each included generation, preserving early GPT models and recent Qwen, Mistral, DeepSeek, Llama, Gemma, and OLMo releases. We exclude instruction/reasoning-tuned variants, specialist models, community fine-tunes, quantized copies, adapters, merges, and test fixtures. This is an illustrative cohort, not a complete census or a global popularity leaderboard.

Vocabulary size does not grow uniformly

The selected measurements include large vocabularies, such as BLOOM and Qwen3.5, alongside compact choices such as Mistral 7B and Granite 3.0. A 50,000-token cutoff would remove real foundation models and bias the picture.

Why do smaller vocabularies persist?

Mistral 7B has 32,000 measured entries; Granite 3.0 8B has 49,152. Vocabulary size is a design choice: at hidden width d, one embedding table contains V × d parameters. Increasing V from 32k to 128k quadruples that table. Whether the extra entries improve compression or model quality must be tested on the target languages and tasks. The scatter alone cannot establish the best vocabulary size.

Rank by an observable usage signal

We rank the exact selected repositories by 30-day Hugging Face downloads observed on 31 October 2026. This is a reproducible way to prioritize case studies. It does not measure unique users, total family adoption, benchmark quality, or practical usefulness.

Popularity is not a quality score

Hub downloads count requests to selected files and can include automated activity. They are affected by caching, distribution channels, and library conventions. See the Hub’s counting rules.

Usability depends on the task

A base model is useful for studying pretraining and further adaptation. Choosing a ready-to-use assistant also requires task evaluations, language coverage, a suitable license, and affordable inference. We do not turn vocabulary size or download counts into a synthetic “usability” score.

Measurement, corrections, and remaining gaps
  • Counting unit. Distinct assigned tokenizer IDs, including serialized added/reserved tokens. Curated rows include inspected companion-file additions; additional bulk rows count the serialized tokenizer JSON only. Each exported row retains its counting scope. These are not padded configuration vocabulary rows, embedding tensor dimensions, or complete multimodal symbol inventories.
  • Dates. The main figure uses sourced release years, never Hub creation dates. SmolLM2’s release year is unverified in this reviewed source set, so it appears in the ranking but not the timeline. The original 11,229-row catalog retains repository proxies for separate exploratory analyses.
  • Deduplication corrected. Kimi K2-Base and K2.5 share a primary rank file but have 163,842 and 163,840 entries after additions. The broad-catalog plots now collapse only verified complete token-to-ID hashes: 637 shared mapping groups plus 20 separate records, or 657 groups/singletons. Even identical primary hashes and counts cannot prove full vocabulary equality. The foundation plots show each selected model separately.
  • Missing measurements. @@MISSING@@. No community tokenizer or configuration row count is substituted for these missing measurements. Rank can still be assigned when a download count exists.
  • Boundary cases. Qwen3-8B-Base is selected instead of the post-trained Qwen3-8B. Qwen3.5’s repository-specific notice says pretraining only, despite a shared overview mentioning post-training. Closed APIs such as GPT, Claude, and Gemini lack comparable Hub download counts and are outside this ranking; their public encoding records remain in the full catalog.
  • Reproducibility. The reader is generated offline from the October 31 snapshot, the original curated measurements, and the explicit selection file. The renamed Llama 3.1 repository is matched through a verified Hub redirect, recorded in the exported data. All plots are embedded vector graphics.
