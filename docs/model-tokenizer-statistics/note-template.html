A complete inventory of the source list

The Wikipedia list, frozen at the inspected revision, contains @@TOTAL@@ table rows from 2018–2026. Every row appears here: open checkpoints, closed APIs, research models, and post-trained releases. A source row may group several sizes or models, so @@TOTAL@@ rows is not a count of distinct checkpoints, nor a census of all LLMs.

We map @@MAPPED@@ rows to an exact representative and retain @@UNMAPPED@@ without a verified mapping. Of the mapped rows, @@TOKENIZERS@@ have measured public tokenizers, @@ENCODINGS@@ have measured public API text encodings, and @@MAPPED_MISSING@@ remain unmeasured. Vocabulary size does not grow uniformly

The larger inventory contains both large and compact vocabularies. The figure uses an exact representative for each measured entry; different releases can share a tokenizer. API text encodings have their own panel because they do not reveal a closed model’s complete vocabulary.

A small vocabulary is a valid design choice

Mistral 7B has 32,000 measured entries; the selected Granite Code 3B checkpoint has 49,152. At hidden width d, one embedding table contains V × d parameters. Increasing V from 32k to 128k quadruples that table. Compression and model quality still need evaluation on the target languages and tasks. A 50k cutoff would discard relevant models and bias the comparison.

Dates need checking too. Wikipedia lists Qwen2.5 under 2025; the official release announcement places it in 2024. We preserve both fields and plot the verified year where available. Repository creation dates are never used in this figure.

Rank by an observable usage signal

Among mapped representatives, @@RANKED@@ have 30-day Hugging Face download counts observed on 31 October 2026. This gives a reproducible ordering for exploring the inventory. Closed APIs and repositories absent from that snapshot remain unranked.

Popularity is not a quality score

Hub downloads count requests to selected files and can include automated activity. They are affected by caching, distribution channels, and library conventions. See the Hub’s counting rules.

Usability depends on the task

A base model is useful for studying pretraining and further adaptation. Choosing a ready-to-use assistant also requires task evaluations, language coverage, a suitable license, and affordable inference. We do not turn vocabulary size or download counts into a synthetic “usability” score.

Measurement, corrections, and remaining gaps
  • Counting unit. Distinct assigned tokenizer IDs, including serialized added/reserved tokens. Curated rows include inspected companion-file additions; additional bulk rows count the serialized tokenizer JSON only. Each exported row retains its counting scope. These are not padded configuration vocabulary rows, embedding tensor dimensions, or complete multimodal symbol inventories.
  • Dates. Listed dates and developers are transcribed source fields, not independently verified facts. The timeline uses the selected representative’s primary-sourced release year when recorded; hollow points use only the Wikipedia year. Neither repository timestamps nor a sibling model’s date fill a gap. Exact release and API snapshot dates can differ within a listed family.
  • Deduplication corrected. Kimi K2-Base and K2.5 share a primary rank file but have 163,842 and 163,840 entries after additions. The separate broad-catalog analysis now collapses only verified complete token-to-ID hashes: 637 shared mapping groups plus 20 separate records, or 657 groups/singletons. Even identical primary hashes and counts cannot prove full vocabulary equality. The figures in this note show each representative separately.
  • Missing measurements. @@MAPPED_MISSING@@ mapped entries remain unmeasured; @@UNMAPPED@@ source entries have no exact representative mapped in this pass. Access restrictions, collection failures, and unsupported artifact formats are recorded separately. This does not establish that a tokenizer is unavailable everywhere. No community tokenizer or configuration count substitutes for a missing measurement.
  • Closed models. Tiktoken and official SDK mappings describe public text encodings, not private control tokens, embedding dimensions, or complete multimodal vocabularies. These appear in their own panel. Claude and other unmapped API vocabularies remain unknown.
  • Representatives. Family-level entries receive at most one exact checkpoint or API snapshot. A grouped row such as “OpenAI o3 and o4-mini” is retained as written, not silently expanded or assigned one sibling’s metrics. The broader inventory uses Qwen3-8B; the pretraining subset separately uses Qwen3-8B-Base. DeepSeek-V4-Flash and Pro use the explicitly listed July/August updates. Exported mapping notes preserve this distinction.
  • Reproducibility. Offline generation joins the attributed Wikipedia inventory, explicit representative mappings, the October 31 catalog, original curated measurements, and additional pinned tokenizer inspections from November 1. Hashes, revisions, counting scopes, dates, and source URLs are exported. The original 11,229-row catalog remains a separate exploratory dataset. This HTML contains its figures, data, filters, and downloads without external runtime dependencies.
